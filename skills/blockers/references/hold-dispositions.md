# Hold dispositions

Disclosed reference for step 1 of [Blockers](../SKILL.md). Load it after classifying
a hold by cause. The skill owns the classification order and the one-line guard for
each branch; this file owns the evidence test, recovery limit and excluded action.

- **Established answer or routine recovery:** inspect repository and session facts
  yourself. Preserve the agreed scope and acceptance; repair the cause and verify the
  supported continuation. A failed check, missing receipt or pending local integration
  does not by itself need a user choice.
- **Idle candidate awaiting delivery:** verify actual writer/session activity and
  candidate identity. When no live writer owns it and local integration is already
  authorized, continue with the existing execution owner and reuse the candidate.
  Keep valid candidate checks, require verification against the integrated code,
  preserve saved settings and private data, and retain no-push, deploy and
  package-delivery exclusions. Do not ask “Pi or this session?” or ask permission to
  reuse the reviewed fix. Do not label this an owner decision or mark delivery
  complete. Separate genuine live qualification still pending.
- **Over-broad resource reservation:** a generic shared reservation that serializes
  unrelated work is a planning repair, not an owner question. Narrow it from evidence:
  the retained diff or candidate decides the task's `touches` and concrete `resources`.
  Keep the reservation where the evidence shows a real global effect (lockfiles,
  migrations, shared generated output, live services) or when there is no evidence.
  Narrow one task at a time, and never change the contract of a task a live worker
  holds.
- **Live or uncertain ownership:** leave live work and claims alone. A `Held by:` note
  or an old ACTIVE label alone proves neither activity nor abandonment, and neither
  does an open session or a bare PID: check the holder's identity and recent writes.
  An unrelated open session in the checkout does not own a claim. If activity cannot
  be established, retain the hold, identify the missing evidence, and continue with
  independent entries. Ask only for information unavailable through inspection; never
  offer an uninformed ownership transfer as the recommended answer.
- **Real owner decision/input:** ask when missing product intent, a scope or acceptance
  change, unavailable external input or ungranted operation authority changes what can
  proceed. State that specific gap. Preserve explicit pauses, cancellations and
  task-specific restrictions; routine local authority does not revoke them. Conditional
  recovery permission ("retry if it crashed") does not establish that the condition
  holds; keep the task held until it is verified.
